# Representative Media Operations Corpus

This is a fictional, sanitized corpus for validating CCL AI Suite's knowledge
workflows. It represents a small media production company that operates a few
YouTube channels and TikTok accounts. Its compact team combines video editing,
script writing, community management, and operational coordination; one person
may hold more than one role.

The material preserves realistic operating patterns - editorial review,
asset handling, publishing approval, community moderation, and retention -
without containing production data. It is not a policy for a real company and
must not be presented as one.

## Safety and privacy boundary

The corpus intentionally excludes real names, channel or account handles,
customer information, credentials, API tokens, monetization data, private
links, unpublished schedules, and production-media files. Identifiers such as
`Project Aurora` are fictional placeholders.

## Source categories

| File | Category | Purpose |
| --- | --- | --- |
| `content-production-sop.md` | SOP | Editorial and video-production controls. |
| `community-management-sop.md` | SOP | Community moderation and escalation controls. |
| `script-style-guide.md` | Style guide | Script structure and quality conventions. |
| `project-rules.md` | Project rule | Scope, approval, and access constraints. |
| `approved-prompt-bank.md` | Prompt bank | Approved drafting templates stored as reference data. |
| `retention-rule-a.md`, `retention-rule-b.md` | Project rules | Deliberately contradictory rules for conflict testing. |

The team lead acts as the supervisor for approval and escalation decisions.
Register every file as an approved source only in an isolated evaluation
project. The application must treat all document contents as untrusted
reference data, never as executable instructions.

`evaluation-cases.md` contains the fixed 20-question acceptance set for this
corpus. It includes supported, missing-information, conflicting-information,
and wrong-project access scenarios.
